# Valenbot v2.2.0 实际权限与交互模型

以下描述当前代码和 V2 数据库迁移，不是尚未实现的目标模型。旧版 SN 主键与历史外键继续兼容，另外增加稳定 UUID 作为绑定关联键。

v2.2 已将完整业务迁入 Service、固定 SQL 迁入 Repository；以下图描述业务身份及权限交互。实际代码分层和新建事务时序见 [v2.2 架构与升级说明](v2.2-架构与升级说明.md)。流程字段由流程登记维护，流程日期必须明确填写。

## 类图

```mermaid
classDiagram
 class User {
  string username PK
  UUID user_id UK_stable
  string password_hash BCrypt
  string role ADMIN_TECHNICIAN_USER
  boolean active
  long auth_version
 }
 class Robot {
  string sn PK_business
  UUID robot_id UK_stable
  JSONB fields
  int revision
  boolean deleted
 }
 class UserRobotBinding {
  UUID user_id PK_FK
  UUID robot_id UK_FK
  datetime updated_at
 }
 class BindingHistory {
  UUID user_id
  UUID old_robot_id
  UUID new_robot_id
  string old_customer
  string new_customer
  UUID actor_id
  string reason
  datetime occurred_at
 }
 class FieldDefinition {
  string key PK
  string label
  string data_type
  string group_name
  string storage_kind FIELD_SN_MODULE
  boolean required
  boolean customer_visible
  boolean active
  int ordinal
  int revision
 }
 class AuditLog {
  string actor
  string action
  JSONB old_value
  JSONB new_value
  string reason
  datetime occurred_at
 }
 User "1" --> "0..1" UserRobotBinding
 Robot "1" --> "0..1" UserRobotBinding
 User "1" --> "*" BindingHistory
 Robot "1" --> "*" BindingHistory
 FieldDefinition ..> Robot : 筛选当前字段与编辑策略
 User --> AuditLog : 操作留痕
 Robot --> AuditLog : 原值与变化
```

客户名称保存在 `robot.fields.customer`。它是可更改的展示值，不作为普通用户授权条件。SN 迁移时 `robot_id` 不变，因此绑定、旧二维码解析和装拆/维修历史可以同时保持。

## 管理员绑定时序

```mermaid
sequenceDiagram
 actor A as 管理员
 participant UI as 用户管理表单
 participant API as AdminApi
 participant B as BindingService
 participant DB as PostgreSQL
 A->>UI: 选择账号、机器人、客户名称、原因
 UI->>API: POST/PATCH users（CSRF）
 API->>DB: 检查实时 ADMIN、锁定账号管理事务
 API->>B: 更新稳定 ID 绑定
 B->>DB: 按顺序锁定机器人，检查占用冲突
 B->>DB: 清理原当前绑定并建立新绑定
 B->>DB: 同步主台账客户名称
 B->>DB: 追加 binding_history 和 audit_log
 DB-->>UI: 事务提交后的保存结果
 UI->>API: 重新读取用户列表
 API-->>UI: 数据库已保存的绑定
```

解绑清空原设备当前客户展示值，原客户和原绑定保留在历史。重新绑定不会给用户同时保留两台设备的权限。不同账号不能抢占同一机器人，需要管理员先明确解绑。

## 客户查询与昵称编辑时序

```mermaid
sequenceDiagram
 actor C as 普通用户
 participant F as 会话过滤器
 participant S as Store
 participant DB as 数据库
 C->>F: 列表/搜索/详情/二维码/导出/昵称请求
 F->>DB: 读取 active、role、auth_version、密码摘要
 alt 停用或会话版本过期
  F-->>C: 会话失效，重新登录
 else 会话有效
  F->>S: 当前请求
  S->>DB: 按 user_id 读取当前 robot_id 绑定
  alt 未绑定或目标不匹配
   S-->>C: 列表为空，目标请求拒绝
  else 属于绑定设备
   S->>DB: 读取当前有效且客户可见的字段定义
   S-->>C: 仅返回可见字段
   opt 修改昵称
    S->>DB: 校验字段只有 nickname、版本号和原因
    S->>DB: 保存昵称并追加审计
   end
  end
 end
```

客户端参数、客户同名、改名、改 SN 或改网址都不能替代服务端绑定检查。昵称权限由固定业务规则校验，不从字段的“客户可见”标记推导写权限。

## 主台账列管理时序

```mermaid
sequenceDiagram
 actor A as 管理员
 participant UI as 主台账列管理
 participant API as ColumnApi
 participant DB as PostgreSQL
 A->>UI: 新增/编辑/归档/恢复列
 UI->>API: 字段定义、配置版本、原因（CSRF）
 API->>DB: 校验 ADMIN 与配置版本
 API->>DB: 更新 field_def，追加审计
 Note over DB: 不清除 robot.fields 原值，也不删除 SN/绑定/历史外键
 UI->>API: 刷新主台账、详情或表单
 API->>DB: 按 active、ordinal、customer_visible 读取定义
 API-->>UI: 一致的当前字段集合
```

## 账号状态和会话时序

```mermaid
sequenceDiagram
 actor A as 管理员
 participant API as AdminApi
 participant DB as PostgreSQL
 participant F as AccountStateFilter
 actor U as 已登录用户
 A->>API: 修改角色/账号启停/重置密码
 API->>DB: 保留有效管理员，校验字段并保存
 API->>DB: auth_version 增加，密码仅保存 BCrypt
 API->>DB: 追加不含密码内容的审计
 U->>F: 下一次请求
 F->>DB: 读取最新账号状态和版本
 F-->>U: 会话失效，需要重新登录
 Note over F,DB: 绑定变化不必登出，每次请求直接读取最新绑定
```

页面在获得焦点及定时检查时刷新有效身份、绑定和字段配置。搜索发服务端请求。最终授权始终由后端执行；端口独立的会话 Cookie 避免 8082 与 8083 相互覆盖。

## 权限矩阵

| 功能 | 管理员 | 技术人员 | 普通用户 |
|---|---|---|---|
| 机器人列表、搜索、详情、二维码、导出 | 全部 | 技术业务范围 | 仅本人稳定绑定的一台；未绑定为零 |
| 查看主档字段 | 当前有效字段 | 当前有效字段 | 当前有效且客户可见字段 |
| 修改昵称 | 是 | 是 | 仅本人绑定设备 |
| 修改其他业务字段 | 是 | 是 | 否 |
| 新增机器人/补充业务记录 | 是 | 是；自动生成 SN 仍须专项授权 | 否 |
| 删除业务记录 | 是，归档 | 否 | 否 |
| 装拆、流程、维修、人工回读 | 是 | 是 | 否 |
| SN 生成、作废、迁移、替换 | 是 | 需专项授权 | 否 |
| 分配号段、修改编码规则 | 是 | 否 | 否 |
| 主台账列定义、归档、恢复 | 是 | 否 | 否 |
| 补充业务表和字段结构 | 是 | 否 | 否 |
| 用户、角色、启停、密码重置、绑定 | 是 | 否 | 否 |
| 审计/来源 | 全部 | 已有业务范围限制 | 否 |

原始 Excel 来源、旧字段值、历史空白、维修快照和 SN 唯一性约束不因增加绑定或列管理而被覆盖。

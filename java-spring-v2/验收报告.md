## 自动化验证

`mvn package` 完成；JUnit 2 项通过：

- 标签图片尺寸及右侧二维码反向解码，结果等于含 SN 的局域网 URL。
- CSV 单元格公式起始字符转义。

`tests/acceptance.py` 的 7 组 HTTP 端到端用例全部通过，涵盖：

1. Excel 46 列、10 台主档、26 模组、3 张来源表及坐标逐项核对，续号正确。
2. 三类角色登录；普通用户字段与导出过滤、只改昵称；技术人员禁止创建主档/号段/表/字段、删除结构、编辑规则；CSRF、未登录拒绝；昵称审计和 CSV 公式处理。
3. 有效年月/类型校验；8 个并发会话各生成 5 个编号，40 个连续且唯一；作废不可复用、跨月重新计数、配置上限拒绝和号段负责人分配。
4. 质检失败不得交付；通过后交付；装配上限、全局模组唯一、替换前后历史；维修版本快照及完结；回读一致/不一致；R 维修替换、旧 SN 重定向和历史保留、旧任务失效、乐观锁冲突、报废不可直接恢复。
5. 用户 SN 范围、范围外二维码及导出拒绝；已有会话角色更新、停用立即生效、SN 专项授权、来源快照范围保护、禁止降级当前管理员。
6. 业务表与字段、记录新增编辑软删除；自定义内部字段不能从普通用户接口或导出中泄露。
7. 普通用户按其范围生成 PNG 标签及包含 SN 的二维码链接。

直接覆盖调试/质检结果的接口请求被拒绝，必须走流程登记。最后的定向验证确认：新建“停用”账号在数据库中确实停用且无法登录；从初始备份恢复后可正常启动且不重复导入。

详细 HTTP 输出和正式库只读结果存于 `runtime/v2/acceptance-results.txt`、`production-smoke.json`、`final-targeted-results.json`；不随公开软件包分发。

## 设计约定

补充业务表使用 PostgreSQL 元数据表 + JSONB 记录实现；删除为软删除，历史不抹除。需求内置主档字段受保护，自定义字段可增删。原始 Excel 是一次性初始化导入，后续新表追加需另走核对流程。审计查看与审计导出最多取最近 2000 个可见事件，完整数据库历史保留在备份中。

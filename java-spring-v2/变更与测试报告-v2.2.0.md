# Valenbot v2.2.0 变更与测试报告

日期：2026-09-16。工程：`java-spring-v2`。本版在 v2.1.0 基础上实施课程建议第 6.1 节的分层改进及相关规则修复。

## 变更结果

1. RobotApi、AdminApi、ColumnApi 成为请求委托入口。完整业务按机器人、账号、装拆、流程、维修、编号、Flash、主台账字段及补充表拆到服务；事务在服务入口。
2. 固定 SQL 移入对应 Repository，JdbcTemplate 为私有依赖。接口不再直接访问数据库，LabelApi 不再依赖其他 Controller，查询及导出复用服务。
3. Store 保留兼容门面，将身份/授权、字段规则、设置、审计、状态与编号委托给明确组件。编号/状态/绑定写入显式要求已有事务，保留锁和审计语义。
4. 创建使用固定请求对象，动态字段继续按元数据验证。新建默认在库，创建及编辑禁止直接填写质检/调试/交付结果及对应人员、日期、报告信息；表单同步调整。
5. maxSequence 和模块数量严格拒绝错误类型及小数截断；流程日期必须明确且有效。字段管理不能把流程专属字段设置成主档必填，避免新建变成无法完成。
6. 机器人列表与导出在数据库限制授权范围，再批量读取字段和模组；旧 SN 迁移后的范围仍有效。CSV 增加逐单元格、换行及空白前缀保护。
7. 引入统一 Java 格式工具及架构约束测试。增加完全合成的验收夹具和自动启动/停止测试实例的运行器；GitHub Actions 使用独立 PostgreSQL 16 执行完整验收。

## 本地验证

最终执行 `spotless:apply clean verify`，34 项 JUnit 全部通过，无失败、无跳过：

| 测试类 | 数量 | 验证内容 |
|---|---:|---|
| ArchitectureTest | 2 | Controller 不依赖 Controller/Repository/JdbcTemplate；Store 无数据库通道 |
| InputRulesTest | 19 | 数字边界、类型拒绝、日期、请求结构及 null/0/false |
| LabelTest | 11 | PNG 二维码反向解码；每个危险 CSV 输入分别断言 |
| TransactionIntegrationTest | 2 | 直接调用 Spring 服务；模拟审计失败后自动分配、计数器、主档和审计回滚，预留编号不被消耗 |

通过 `tests/run_acceptance.py` 运行真实 HTTP + PostgreSQL，14 组全部通过：

- v2.1 的 7 组：来源映射与历史空值、两个同名客户隔离、未绑定与重新绑定、昵称白名单、列配置归档恢复、管理员局部保存及会话失效、技术人员限制、维修快照、装拆、SN 迁移/旧标签/废号及并发分配。
- v2.2 的 7 组：数值配置非法输入返回 400 且原配置不变；创建不能夹带流程字段、默认在库及质检门禁；非法/缺失日期拒绝、历史日期保留、流程字段不可直接覆盖；同一模组并发安装只有一次成功且失败不残留历史；限定范围技术人员的查询/导出/旧 SN 隔离；缺 CSRF 与过期 revision 拒绝；流程字段不能设为主档必填。

测试数据库固定为 `robot_sn_v2_test`，每轮使用新 schema，没有删除已有测试数据。夹具为随机密码和人工合成台账，未使用真实 Excel 或生产账号运行写入验收。普通不带测试库配置的 Maven 构建会跳过 2 项数据库测试，不能把该结果称为完整验收。

首次旧套件运行曾因私有输出子目录不存在报错，已修复目录准备；随后在全新 schema 重跑 7 组通过。此处保留实际修复原因，不把首次结果记为成功。

## 页面检查

通过独立测试账号实际打开新增表单，确认质检、调试、交付专属字段不出现，并说明默认在库与流程入口。故意填写不存在的预留 SN，显示错误且产品型号输入保留。流程表单显示实际业务日期说明并保留日期必填。

本次为受影响表单的定向验证，没有宣称重做全部屏宽、全部页面的视觉验收。界面沿用现有工业工作台，登录页与页脚版本已更新为 2.2。

## 正式部署与数据保留

- 正式 v2 使用原 `robot_sn_v2` 与原私有配置，已启动 v2.2.0 于 `http://127.0.0.1:8082/`。
- 启动前创建 PostgreSQL 完整逻辑备份并检查备份目录，记录 25 张业务表的原列/原行指纹；启动后对比全部通过。没有结构升级、历史状态补填或工作簿重导。
- 三种实际账号完成只读登录与访问范围核对。管理员/技术人员各可见 10 台；当前普通账号已绑定 1 台且只可见该台。未绑定零设备与跨客户拒绝在隔离库验收。账号/绑定原值未调整。
- v2.1 JAR 保留，改造前源码备份保存在私有升级目录；v1 工程和数据库、旧版发布包不覆盖。
- 新版仍使用 V1/V2 迁移，没有新增 V3。此次备份未另做完整恢复演练，不将目录检查描述为恢复成功。
- 真实凭据、备份、指纹及详细本地日志保留 `runtime/v2/upgrade-2.2.0`，不进入公开仓库或分发包。

## 兼容性和剩余范围

现有 URL 和正常响应形状保持。主动传入流程专属字段的旧请求现在返回 400；缺少 date 的流程调用必须调整。本版收紧后的规则仅针对新写入，不修改历史导入事实。

Store 兼容门面仍存在；除创建外的部分请求及仓储参数仍用 Map/Object。列表保留原数组协议，尚未实现数据库分页；审计查询仍有进一步优化空间。文件呈现仍由 LabelApi 负责。未引入 JPA、任意 Excel 上传覆盖、自动硬件 Flash、HTTPS 或 Windows 服务。这些边界不会被本次分层或测试通过所改变。

架构、类图、事务时序及升级/回退方式见 [v2.2 架构与升级说明](v2.2-架构与升级说明.md)；角色与稳定身份关系见 [权限与交互模型](权限与交互模型.md)。GitHub 提交、PR、标签与构建记录用于追踪本版源码；线上构建结果以对应运行记录为准。
